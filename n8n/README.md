# Автоматизация Navi на n8n

Три воркфлоу, закрывающие процессы из кейса: обработку заявок, ведение
библиотеки документов и работу ролевых агентов по расписанию.

## Импорт

В n8n: **Workflows → Import from File** → выбрать файл из этой папки.
Импортировать по одному.

## Переменные окружения n8n

**Settings → Variables** (или Environment на self-hosted):

| Переменная | Значение | Где используется |
|---|---|---|
| `NAVI_API_URL` | `https://navi-backend-2x2q.onrender.com` | 02, 03 |
| `NAVI_TELEGRAM_CHAT_ID` | ID чата или канала деканата | 01, 03 |
| `NAVI_DOCS_SOURCE_URL` | URL источника документов вуза | 02 |

Для узлов Telegram нужно один раз добавить учётные данные бота:
**Credentials → New → Telegram API** → токен от @BotFather.

## 01 · Заявки в деканат

**Что делает.** Когда агент не может ответить своими документами,
пользователь отправляет заявку. Бэкенд Navi шлёт событие в n8n, n8n
присваивает номер, определяет адресата по роли автора и отправляет
сообщение в Telegram деканата.

**Маршрутизация по ролям** — то, ради чего здесь нужен n8n: заявка
студента уходит в учебный отдел, преподавателя — на кафедру,
администратора — в канцелярию.

**Подключение.** После импорта откройте узел «Событие из Navi» и
скопируйте Production URL вебхука. Впишите его в Render:

```
navi-backend → Environment → N8N_WEBHOOK_URL = <скопированный URL>
```

Важно: бэкенд отправляет событие и не ждёт ответа. Если n8n выключен
или недоступен, пользователь этого не заметит — основной сценарий не
ломается.

## 02 · Синхронизация библиотеки документов

**Что делает.** Каждый день в 06:00 забирает документы из источника
вуза, отсеивает пустые и слишком короткие, и загружает в библиотеку
Navi через `/documents/upload`. Загруженные документы сразу попадают в
поисковый индекс своей роли.

**Формат источника.** `NAVI_DOCS_SOURCE_URL` должен отдавать JSON:

```json
[
  { "title": "Регламент сессии", "content": "полный текст…", "role": "student" },
  { "title": "Приказ №128",      "content": "полный текст…", "role": "admin"   }
]
```

Поле `role` определяет, какому агенту документ станет доступен. Если
роль не указана или неизвестна — документ уйдёт студенческому агенту.

**Расписание** меняется в узле «Каждый день в 06:00»: выражение
`0 6 * * *` — ежедневно в 6 утра.

## 03 · Утренний дайджест ролевых агентов

**Что делает.** По будням в 08:00 задаёт каждому из трёх агентов свой
вопрос через `/chat`, собирает ответы в один дайджест со ссылками на
источники и отправляет в Telegram.

**Почему вопросы разные.** Одинаковый запрос дал бы трём агентам
похожие ответы, а смысл ролевой модели в том, что каждому нужна своя
сводка: студенту — дедлайны, преподавателю — организационные
материалы кафедры, администратору — сроки рассмотрения заявлений.
Ответы будут построены на разных документах, потому что у агентов
разные индексы.

**Тексты вопросов** правятся в узле «Вопрос под каждую роль».

---

## Проверка

1. **Заявки:** откройте Navi, задайте вопрос, нажмите под ответом
   «Отправить заявку в деканат» → сообщение должно прийти в Telegram.
2. **Синхронизация:** нажмите **Execute Workflow** вручную, затем
   откройте библиотеку в Navi — новые документы появятся в списке.
3. **Дайджест:** тоже **Execute Workflow**, ждать 08:00 не нужно.

## Если что-то не работает

| Симптом | Причина |
|---|---|
| Заявка не приходит | `N8N_WEBHOOK_URL` не задан в Render или указан Test URL вместо Production |
| Telegram молчит | Не добавлены учётные данные бота или неверный `NAVI_TELEGRAM_CHAT_ID` |
| Документы не загружаются | Источник отдаёт не тот формат, либо `content` короче 120 символов |
| Дайджест приходит пустым | Бэкенд «спал» — первый запрос на бесплатном тарифе Render идёт до минуты |
